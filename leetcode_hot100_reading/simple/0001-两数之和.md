# 1. 两数之和 · 阅读版

> 难度：简单 · [LeetCode 链接](https://leetcode.cn/problems/two-sum/)

---

## 一、题目讲了什么

给一个整数数组 `nums` 和目标值 `target`，找出数组里**和为 `target`** 的**两个**数，返回它们的**下标**（不是值）。

例：`nums = [2, 7, 11, 15], target = 9` → 因为 `2 + 7 = 9`，答案是 `[0, 1]`。

题目保证恰好有一个解，不能用同一个元素两次。

---

## 二、最朴素的想法

双层 for：每个 `i` 配上每个 `j > i`，检查和是否等于 target。

```python
for i in range(n):
    for j in range(i + 1, n):
        if nums[i] + nums[j] == target:
            return [i, j]
```

正确但慢：`O(n²)`。题目数据规模 10⁴，乘起来 10⁸ 操作量级，能过但显然不优雅。问题在于"每个 `i` 都把右边全扫一遍"——大量重复工作。

---

## 三、换个角度：哈希表"以查代算"

固定 `nums[i]` 时，我们其实在问一个简单问题：**`target - nums[i]` 在不在数组里？**

如果我们能 O(1) 回答这个问题，整体就降到 O(n)。能 O(1) 查"某个值在不在"的数据结构，就是**哈希表**。

但还有个细节：返回的是**下标**，不是值。所以哈希表存的是 `值 → 下标`。

---

## 四、为什么要"边查边存"，不能"先存后查"

一个常见的错法：先把所有数全塞进哈希表，再遍历找 `target - nums[i]`。这会引入两个 bug：

1. **同一个元素被自己配对**：`nums = [3, 4, 6], target = 6`，遍历到 3 时找 `target - 3 = 3`，哈希里确实有 3——但那个 3 就是自己。
2. **遇到 `[3, 3], target = 6` 时**：哈希表 `{3: 1}`（后面的 3 覆盖了前面的），返回 `[1, 1]` 错的。

正确做法：**边遍历边登记**——

> 先查 "`target - x` 在不在表里"，**再**把当前 x 登记进去。

这样查的时候，表里只有"**严格在我之前**出现过的数"，自配对和重复都不会出问题。

---

## 五、写成代码

```python
class Solution:
    def twoSum(self, nums: list[int], target: int) -> list[int]:
        # 哈希表：键是"出现过的数值"，值是它的下标
        seen: dict[int, int] = {}
        # 遍历数组，i 是当前下标，x 是当前数值
        for i, x in enumerate(nums):
            # 计算"凑成 target 还差多少"
            need = target - x
            # 如果差值之前出现过，说明配对成功
            if need in seen:
                # 返回那个数的下标和当前下标
                return [seen[need], i]
            # 没配上就把当前数登记进哈希表，留给后面的数来配
            seen[x] = i
        # 题目保证有解，理论上走不到这里
        return []
```

---

## 六、复杂度

- **时间** `O(n)`：单趟遍历，哈希查询 / 插入都是 O(1)
- **空间** `O(n)`：最多把整个数组登记进哈希表

---

## 七、容易踩的坑

1. **顺序：先查后存**。颠倒就会让元素配对自己。
2. **返回下标不是值**。所以哈希存 `值→下标`，不是 `值→值`。
3. **题目没要求下标有序**，返回 `[i, j]` 还是 `[j, i]` 都对。

---

## 八、一句话记忆

> 看见"找两个和等于 X" → 哈希表存"值→下标"，**先查 `target-x` 再登记自己**。
