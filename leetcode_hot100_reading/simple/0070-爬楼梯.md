# 70. 爬楼梯 · 阅读版

> 难度：简单 · [LeetCode 链接](https://leetcode.cn/problems/climbing-stairs/)

---

## 一、题目讲了什么

爬一段共 `n` 阶的楼梯，每次能爬 **1 阶或 2 阶**。问爬到顶有**多少种**不同方法。

例：

- `n = 2` → `[1+1, 2]`，**2 种**
- `n = 3` → `[1+1+1, 1+2, 2+1]`，**3 种**

---

## 二、倒着想：最后一步是怎么上来的

直接正着列举 `n` 阶的所有走法太混乱。换个视角——**站在第 n 阶，回头看最后那一脚**：

- 要么从第 `n-1` 阶迈了 **1 阶**上来
- 要么从第 `n-2` 阶跨了 **2 阶**上来

所以：

> 到达第 n 阶的方法数 = 到达 n-1 阶的方法数 + 到达 n-2 阶的方法数

记 `f(n)` 是答案：

```
f(n) = f(n - 1) + f(n - 2)
```

这就是**斐波那契数列**的递推。

---

## 三、找边界

递推得停在某些已知值上：

- `f(1) = 1`（只有一种走法：1）
- `f(2) = 2`（两种：1+1，2）

也可以约定 `f(0) = 1`（"什么都不爬"算一种"方案"），这样让公式从 `n = 2` 开始就成立。

---

## 四、为什么不写递归

直接 `return f(n-1) + f(n-2)` 是会爆栈 / 爆时间的：

```
f(5)
├── f(4)
│   ├── f(3)
│   │   ├── f(2)
│   │   └── f(1)
│   └── f(2)        ← 又算了一次 f(2)
└── f(3)             ← 又算了一次 f(3)
    ├── f(2)        ← 又算了一次 f(2)
    └── f(1)
```

子问题反复重算，复杂度变成 `O(2ⁿ)`。

**解决**：从小到大**迭代**算上去，每个 f(k) 只算一次。

---

## 五、从二维 dp 压到 O(1) 空间

更进一步：算 `f(n)` 时只需要前两个值 `f(n-1)` 和 `f(n-2)`，不需要把整个数组留着。用两个变量滚动即可：

```
a = f(0) = 1
b = f(1) = 1

每次更新：(a, b) → (b, a + b)
            旧 a 丢掉，旧 b 变新 a，旧 a + 旧 b 变新 b

滚 n 次后，a 就等于 f(n)
```

> 形象化：两个口袋每次往前挪一格，前面那个口袋装"上一个"，后面那个装"再上一个"。

---

## 六、写成代码

```python
class Solution:
    def climbStairs(self, n: int) -> int:
        # a 表示 f(0)、b 表示 f(1)，都视为 1 种方案
        a, b = 1, 1
        # 滚动 n 次，每次让 (a, b) 变成 (b, a+b)
        # 含义：原本的 b 变成新 a，原本的 a+b 变成新 b
        for _ in range(n):
            a, b = b, a + b
        # 滚动 n 次后，a 恰好等于 f(n)
        return a
```

Python 元组赋值原子操作，不用担心 `a, b = b, a + b` 时谁先谁后。

---

## 七、复杂度

- **时间** `O(n)`：n 次循环
- **空间** `O(1)`：两个变量

---

## 八、容易踩的坑

1. **递归不加 memo 会超时**：朴素递归 `O(2ⁿ)`，n=30 就会卡。
2. **初始值常错**：`f(0)` 是 1（不是 0）。和经典斐波那契的偏移要对清楚。
3. **循环次数对 n 不对 n-1**：迭代 n 次后 `a == f(n)`；想清楚滚的次数。

---

## 九、一句话记忆

> 站在第 n 阶**回头看**最后一脚：要么 1 步要么 2 步上来 → 斐波那契递推 → 两个变量滚 n 次。
