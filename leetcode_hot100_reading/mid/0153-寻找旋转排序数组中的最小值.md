# 153. 寻找旋转排序数组中的最小值 · 阅读版

> 难度：中等 · [LeetCode 链接](https://leetcode.cn/problems/find-minimum-in-rotated-sorted-array/)

---

## 一、题目讲了什么

升序数组被旋转后（如 `[3,4,5,1,2]`），找最小元素。要求 O(log n)，所以二分。

---

## 二、规律：和右端点比

最小值就在"两段升序的拼接处"。每次二分把 mid 和**右端点 nums[hi]** 比：

- `nums[mid] > nums[hi]`：mid 在**左段**（较大段），最小值在 mid 右边
- `nums[mid] < nums[hi]`：mid 在**右段**（较小段），最小值在 mid 处或它左边
- `nums[mid] == nums[hi]`：本题保证无重复，不会发生

---

## 三、为什么不能和 nums[lo] 比

反例：`[1, 2, 3, 4, 5]`（未旋转）。

- 和 nums[lo] 比：`nums[mid] > nums[lo]` 恒成立 → 一直缩到右半，但最小值是 nums[0]，错。
- 和 nums[hi] 比：`nums[mid] < nums[hi]` → 缩到左半，正确。

未旋转的特例提醒我们**比右不比左**。

---

## 四、写成代码

```python
class Solution:
    def findMin(self, nums: list[int]) -> int:
        lo, hi = 0, len(nums) - 1
        while lo < hi:
            mid = (lo + hi) // 2
            # 关键：和右端点比，不是和左端点
            if nums[mid] > nums[hi]:
                # mid 在左段（较大的段），最小值在 mid 右边
                lo = mid + 1
            else:
                # nums[mid] <= nums[hi]：mid 在右段，最小值在 mid 或 mid 左边
                hi = mid
        # 收缩到 lo == hi 时就是最小值位置
        return nums[lo]
```

---

## 五、复杂度

- **时间** `O(log n)`
- **空间** `O(1)`

---

## 六、容易踩的坑

1. **比 `nums[hi]`，不比 `nums[lo]`**：理由见上。
2. **`hi = mid`（不是 mid - 1）**：mid 自己可能是答案。
3. **循环条件 `lo < hi`**：闭区间收缩到单点即答案。

---

## 七、一句话记忆

> 旋转数组找最小：**mid 和 nums[hi] 比**，大于则缩左 (lo=mid+1)，否则缩右 (hi=mid)。
